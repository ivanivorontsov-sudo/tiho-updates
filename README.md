# tiho-updates

Публичный канал подписанных обновлений для браузера **Тихо** (`org.ivanivorontsov.tiho`: 1.1.x на WebView и 2.x на GeckoView).
Здесь лежат только данные. Исходники браузера хранятся в отдельном приватном репозитории.

| Путь | Что это |
|---|---|
| `content/manifest.json` + `.minisig` | Манифест пакета содержимого: версия, срок действия, `min_app_version`, `min_webview_major`, SHA-256 и размер каждого файла |
| `content/packs/<N>/…` | Файлы пакета N: списки фильтров (`filters/`), фишинг/malware-списки (`security/`), JS-шимы защиты (`js/`), `payment-domains.json`, каталог userscripts |
| `app/update.json` + `.minisig` | Обновление для Тихо 1.1.0 (WebView): указывает на мост 1.1.1 (APK ≤ 64 МиБ). Подписывается только офлайн-ключом |
| `app/update-v2.json` + `.minisig` | Обновление для Тихо ≥ 1.1.1: APK на GeckoView по ABI (`apks`: arm64-v8a, armeabi-v7a, x86_64), `gecko_version`. Подписывается CI-ключом |
| Релизы `app-vX` | Сами APK (GitHub Releases, до 200 МиБ) |
| `userscripts/` | Userscripts из каталога. Их SHA-256 закреплены в `catalog.json` внутри подписанного пакета |
| `keys/*.pub` | Публичные ключи подписи обновлений в формате minisign (Ed25519) |

## Как приложение проверяет обновления

1. Скачивает `manifest.json` и `manifest.json.minisig`. Используется только HTTPS (`raw.githubusercontent.com`).
2. Проверяет подпись Ed25519 одним из двух ключей, вшитых в приложение: основным или резервным. Ключ подписи APK для этого **не** используется.
   Подписанный комментарий (trusted comment) должен называть ту же версию пакета.
3. Пакет отклоняется, если:
   - версия не больше уже принятой (это защищает от отката и повтора);
   - срок действия истёк;
   - приложение старше, чем `min_app_version`.
4. Каждый файл скачивается во временный каталог и сверяется с размером и SHA-256 из манифеста.
   Затем пакет атомарно подменяет текущий. Предыдущая версия сохраняется.
5. Если с новыми списками блокировщик не собирается, приложение автоматически возвращает предыдущую версию.
6. Список платёжных доменов только дополняется: обновление не может убрать встроенные или ранее известные домены.
7. Обновление APK устанавливается только после подтверждения пользователем. Приложение проверяет:
   - подпись `update.json`;
   - SHA-256 скачанного APK;
   - имя пакета и versionCode;
   - сертификат подписи APK. Он должен совпадать с вшитым: `F1:72:85:19:60:CF:08:63:34:B7:14:91:FB:DC:48:89:86:1E:1E:EB:60:7E:4F:2D:40:6C:BD:86:FF:90:D6:D0`.

## Ключи

| Ключ | Key ID | SHA-256 открытого ключа |
|---|---|---|
| Основной | `ED285F174C49C57B` | `0B:C1:0A:D6:83:E3:1D:22:36:07:C6:08:66:18:09:CB:BA:69:47:95:C5:1C:69:59:BB:2C:0F:A9:17:0B:8D:09` |
| Резервный | `5A83C100C35A8CFA` | `76:C9:25:51:01:85:1D:68:01:6C:F2:84:5F:85:1D:49:B0:20:48:FB:64:D6:7F:FC:DE:CD:0D:64:FE:1E:CE:5F` |
| CI (только APK) | `318330A73A3A41D8` | `keys/tiho-content-ci.pub` |

**Ключ CI.** GeckoView выходит раз в 2–4 недели, и каждое исправление движка — это новый APK. Ежедневный workflow в приватном репозитории
браузера сам собирает и публикует сборку. Чтобы не держать в CI офлайн-ключи (они подписывают ещё и списки фишинга, платёжные домены и каталог
userscripts), у CI свой третий ключ Ed25519. Приложение принимает его **только** для `app/update-v2.json`, а пакеты содержимого — только с
основным и резервным ключом. Новой власти CI-ключ не даёт: CI и так хранит ключ подписи APK, а приложение дополнительно сверяет сертификат
APK, имя пакета, versionCode и SHA-256. Утечка CI-ключа без ключа APK не позволит подсунуть чужой APK; утечка обоих — уже компрометация CI,
от которой отдельный ключ не спас бы.

**Как CI публикует.** Сборка пушит APK (частями по 45 МБ: лимит git — 100 МБ) и подписанный `update-v2.json` в ветку `incoming`
через deploy key с правом записи. Workflow `publish-app` склеивает части, проверяет подпись и SHA-256/размер (`tools/check-incoming.py`),
создаёт релиз `app-vX`, коммитит описание в `main` и удаляет `incoming`.

Проверить подпись вручную можно так: `minisign -Vm content/manifest.json -p keys/tiho-content-primary.pub`.

## Источники списков

Списки фильтров берутся из своих первоисточников и распространяются на их условиях:
- EasyList / EasyPrivacy / RU AdList / Fanboy;
- uBlock Origin uAssets;
- AdGuard;
- Peter Lowe;
- HaGeZi;
- malware-filter: phishing-filter, URLhaus.

`payment-unbreak.txt` — это исключения Тихо для антифрод- и 3-D Secure-скриптов на страницах оплаты.
